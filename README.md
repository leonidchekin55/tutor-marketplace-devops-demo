# КодСтарт — демо-маркетплейс репетиторов

Статическая адаптивная страница на русском языке для вымышленного маркетплейса занятий программированием для детей. Проект демонстрирует короткий CI/CD-процесс без собственного сервера и секретов хостинга.

## Как устроен CI/CD

GitHub Actions запускает workflow при каждом pull request в `main`, push в `main` и вручную. Сначала runner получает код, устанавливает Node.js 22 и зависимости из зафиксированного lock-файла pnpm, затем выполняет ESLint и модульные тесты. Только при успешном завершении проверок для push в `main` (или ручного запуска) загружается артефакт и отдельная job публикует его в GitHub Pages. Pull request проверяется, но не публикуется. Права Pages выдаются только задаче деплоя; параллельные запуски для одной ветки отменяются, чтобы не публиковать устаревший результат.

GitHub Pages выбран для простой статической демо-страницы: отдельный сервер, контейнеры и секретный токен хостинга не нужны. В настройках репозитория нужно включить Pages с источником **GitHub Actions**. Публичный URL будет иметь вид `https://<владелец>.github.io/<репозиторий>/` и появится в окружении `github-pages` после первого успешного деплоя. Для production-приложения с API или серверным рендерингом можно выбрать Vercel/Netlify.

## Мониторинг доступности

Для демо достаточно бесплатной HTTP-проверки UptimeRobot каждые 5 минут по URL GitHub Pages. Проверять следует главную страницу и ожидаемый HTTP-код 200; уведомления об инциденте и восстановлении направлять владельцу по email или в Slack. Настроить повторную проверку перед оповещением, чтобы снизить ложные тревоги, и указать второй контакт. Синтетический мониторинг проверяет, что сайт доступен извне; он не заменяет проверку ошибок JavaScript или корректности контента. При появлении приложения/API добавить Sentry для клиентских ошибок и health endpoint для backend.

## Локальная проверка

```sh
pnpm install --frozen-lockfile
pnpm run lint
pnpm test
```
